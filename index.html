01Agent Map

我的工具足迹

我用的工具不多，三个，而且分工非常清楚。对我来说，选择 Agent 的依据不是它有多强，而是它能不能干净地嵌进我本来就在做的那件事里。

AGENT_01 使用最多

DeepSeek harness ／ 写代码

目前几乎所有的代码都从这里出。主要场景是在 Linux 环境里跑深度学习——数据预处理、训练脚本、指标对比、报错排查。 我手头的论文复现工作基本靠它推进：我负责把方法读懂、把目标讲清楚，它负责把想法变成能跑的东西。

深度学习训练Linux论文复现调试
AGENT_02 用得最久

WorkBuddy ／ 翻译文章

最早接触的一个，也是用法最单一的一个：翻译。学术论文、技术文档、英文说明，整段丢进去，出来的是能直接读下去的中文。 它不参与写代码，但读文献的速度完全不一样了——尤其是那些术语密集、公式夹在句子中间的部分。

学术翻译文档处理日常高频
AGENT_03 偶尔使用

zcode ／ 做 PPT

用得最少，目前只做过几份 PPT。把内容整理好交给它，让它排成一页页的东西。 适合那种内容其实已经想清楚了、只差呈现的时刻——它解决的是排版和结构，不是思考。

02Workflow

一条任务，三个工具

它们不是并列的三个选项，而是一条链上的三段。这是一篇论文从"看不懂"到"做出东西"的真实路径。

STEP 01WorkBuddy

先把论文读进去

英文原文先过一遍翻译，重点章节反复读。这一步的目标不是"看完"，而是搞清楚作者到底做了什么、哪一步是可以复现的。

STEP 02自己

拆成能执行的任务

把方法拆成数据、模型、训练、评估几块，写下来。这一步我不交给 Agent——想不清楚的部分，交出去只会更乱。

STEP 03DeepSeek harness · Linux

写代码，跑通最小的一段

先跑一个最小可运行的版本，确认数据能进、输出是对的，再往上加模块。大部分时间花在这里，也大部分问题出在这里。

STEP 04macOS

结果回到本地整理

训练在 Linux 上跑，写东西在 macOS 上。结果、曲线、日志拉回来整理，顺手用本地算力做小规模的验证。

STEP 05zcode

最后才谈呈现

需要汇报的时候，把已经确认的结论交给它排成 PPT。内容在前，样式在后，顺序反了就得重来。

03Playbook

五条协作心得

用得不久，但踩过的坑都记住了。下面这些不是方法论，是被现实纠正过的习惯。

01 / 起点

从一件真事开始，别为了用而用

我第一次正经用它，是因为一篇论文实在读不下去。任务真实、边界清楚、结果好不好一眼能看出来——这是最合适的起点。为了"试试新工具"而找任务，通常两次之后就放弃了。

02 / 前置

先让它复述一遍

复杂一点的活，先让它说说打算怎么做。多数时候这一步暴露的不是它理解错了，而是我自己的表述有洞——有些条件我压根没写进去，却以为它知道。

03 / 节奏

小步验证，不允许静默升级

跑代码尤其明显：先跑通最小的一段，再往上加。依赖、版本、参数，任何改动都必须说出来。悄悄换掉的东西，最后都要花更多时间还回去——而且是带着双倍的困惑还。

04 / 分工

一个工具，一类事

翻译交给 WorkBuddy，代码交给 DeepSeek harness，PPT 交给 zcode。听起来不灵活，但每次换工具都要重新交代一遍上下文——省下的切换成本，远大于那点"灵活性"。

05 / 环境

把运行环境交代清楚，能省掉一半返工

我在 macOS 上写东西，在 Linux 上跑训练，两边的路径、显卡、依赖版本、Python 环境都不一样。第一次没说清楚的时候，它给我的命令在我自己机器上一行都跑不了。现在我会在开头就写明白：什么系统、什么卡、什么版本、报错原文是什么。这一个习惯，省下来的时间比任何提示词技巧都多。

Agent 不会替我把问题想清楚。它只是让我在想清楚之后，能更快地看到结果。 — 用了一个月之后最直接的一句话
04About

关于我，和下一步

我是严靖。目前在做的方向很具体：把论文里的东西真正做出来——手头是一篇深度学习工作流的复现， 从读原文、搭环境、写训练代码，到把结果和原文对齐。日常是 macOS 上写东西、Linux 上跑代码。

使用 Agent 的时间并不长。这三个工具也不是同时开始用的：先是为了翻译，后来是为了写代码，最后才是做 PPT。 每一次都是因为手上有件必须做完的事，才去找一个能帮上忙的东西。

所以这份报告里没有"效率提升 300%"这种数字。能确定写下来的只有：读文献快了，写代码时少卡在语法上， 以及慢慢学会了一件事——把要求说清楚，比把要求说多，重要得多。

Next / 接下来想试的

  1. 让 Agent 参与读别人的仓库，而不只是写我自己的代码
  2. 把复现流程整理成一套可复用的脚本，下次不用从头再来
  3. 试试让它帮忙整理实验结果和图，而不只是最后做 PPT
